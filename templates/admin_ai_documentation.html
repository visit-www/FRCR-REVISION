Architecture Overview
How AI is Used
  • All AI calls go through ai_client.py → Anthropic Messages API (requests.post)
  • No SDK — raw HTTP to api.anthropic.com/v1/messages
  • 3 model tiers: Opus (premium), Sonnet (default), Haiku (lightweight)
  • 24 distinct AI call sites across the application
  • Every call logged to AIAuditLog with input+output tokens

ACTION_PROMPTS['sba'] ai_smart_reporter.py
Create 3 FRCR Part 2B style Single Best Answer (SBA) questions. Each tests a DIFFERENT knowledge domain: - Q1: Directly about the imaging findings/diagnosis from this case - Q2: Related differential diagnosis or mimicking condition (standalone) - Q3: Broader principles (classification, variant, guideline, complication) Q2 and Q3 should be standalone — answerable without knowing the specific case. Format as HTML with <div class='sba-question'> wrapping. 5 plausible options per question, FRCR 2B difficulty. 2-3 paragraph explanations covering correct answer and all distractors.
ACTION_PROMPTS['viva'] ai_smart_reporter.py
Create an FRCR Part 2B style viva (oral examination) scenario. Examiner-candidate dialogue that progressively explores the case. CRITICAL: Must be self-contained — no assumption candidate can see images. First question PRESENTS the key findings (does NOT say "describe the findings"). 4-6 exchanges: findings → interpretation, differential, likely diagnosis, further imaging, management, pitfalls. Model answers should be consultant-level, structured, and concise.
Cost Tracking System
How It Works
  1. ai_client.call_claude() stores {input_tokens, output_tokens} in call_claude.last_usage after each API call
  2. Route handlers call track_ai_call() or log_ai_usage() which reads tokens and writes to AIAuditLog
  3. Admin dashboard queries AIAuditLog and calculates costs using MODEL_COSTS from ai_cost_tracker.py
  4. Admin users see inline $0.00XX cost badge on every AI response in Smart Reporter
Dashboard API

GET /api/admin/ai-costs?days=30&user_id=X — returns:

  • summary: total requests, total cost, avg cost per request
  • by_category: admin_generation (fixed overhead) vs user_interaction (scales with subscribers)
  • by_user: per-user breakdown with requests, tokens, cost
  • by_action: cost per feature (ai_assist, radiq_query, etc.)
  • by_day: daily cost trend
  • by_model: cost per exact model version
  • by_family: simplified Opus / Sonnet / Haiku split
Business Model Insight
Admin generation cost = fixed overhead (algorithms, templates, TNM, cases, protocols). Does not grow with users.
User interaction cost = variable (reports, Q&A, vetting, RadIQ, SBA/Viva). Scales with subscriber count.
Key metric: user interaction cost per active user per month — this is your marginal cost of serving one subscriber.
RadInsight Peer Review
What It Does
  • Post-processes AI output to extract numerical claims (measurements, percentages, thresholds)
  • Verifies claims against PubMed indexed literature
  • HEAD-checks Radiopaedia article URLs (only shows verified clickable links)
  • Annotates claims with trust tiers: Verified or Unverified

Flag Inaccuracy

Users can flag incorrect claims via the Flag Inaccuracy button on any peer-reviewed content. Flags are stored in PeerReviewFlag table with content type, section, and user description. Admin can review via SELECT * FROM peer_review_flag WHERE is_resolved = false.
